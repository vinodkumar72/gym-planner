# Database

SQLite via `expo-sqlite`, schema in `src/db/schema.ts` (Drizzle). Migrations are generated by `drizzle-kit generate`
into `drizzle/` and bundled into the app. `PRAGMA foreign_keys=ON` and `journal_mode=WAL` are set when the DB opens.

## Tables

| Table | Purpose | Notes |
|---|---|---|
| `exercises` | library (built-in + custom) | `kind` weighted/bodyweight/timed/cardio, `min_load` for barbell lifts, JSON `secondary_muscle_groups` |
| `routines` | routine header | `rotation_type` rotation/calendar, `is_active`, `is_builtin`, `is_archived`, `activated_at` |
| `workout_templates` | workout days inside a routine | ordered by `position` |
| `template_exercises` | exercise prescription in a template | sets, rep range, rest, increment + unit, timed/cardio targets |
| `routine_schedule` | calendar mode weekday assignments | unique (routine, day_of_week) |
| `workout_sessions` | one performed workout | snapshots `template_name`, `local_date`, `readiness`, rest-timer state, `status` |
| `session_exercises` | exercise performed in a session | snapshot `exercise_name`, status pending/completed/skipped/substituted, `substituted_from_exercise_id` |
| `exercise_sets` | individual sets | `set_type` warmup/working, reps, `weight` + `weight_unit`, duration, distance, rpe, rir, completed |
| `recommendation_history` | progression results computed at finish | action, reason, prescription JSON |
| `user_preferences` | single row `default` | units, days, rest, theme, notifications, onboarding |
| `app_meta` | key/value | seed version etc. |

## Integrity rules

* Sessions reference templates with `ON DELETE SET NULL`; the snapshot columns keep history readable after edits.
* `session_exercises.exercise_id` uses `ON DELETE RESTRICT`: an exercise with history cannot be hard-deleted (archive instead).
* `template_exercises` cascade with their template; `workout_templates` cascade with their routine; sessions do not.
* All multi-table writes (start/finish workout, duplicate routine, restore backup) run in one transaction.

## Testing

`tests/helpers/testDb.ts` opens an in-memory libsql database and runs the same generated migrations, so repository
and service tests exercise the real SQL, foreign keys and indexes.
